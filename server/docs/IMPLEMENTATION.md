## 1 状态与证据口径

- **已开发**：存在可执行代码、接口和持久化规则；不等于用户已验收。
- **自动测试通过**：确定性测试覆盖正常、拒绝或异常路径；测试模型和测试账号仅用于核验代码。
- **真实模型样本验收通过**：真实模型完成工具调用与岗位交接，数据库、文件和报告内容与该组原始测试资料一致；须同时通过技术链路和语义质量核对。状态只适用于已列明样本，仅技术流程跑通不能使用该状态。
- **人工试用通过**：实际员工办理真实业务，业务负责人核对结果与实际节省工作；目前未开始。
- **正式发布通过**：商业发布阻塞项清零，业务、产品、技术、测试、运维五方签核并完成生产检查；目前未开始。

新增变更只更新所影响的需求和证据。后续功能已开发，不得据此自动勾选人工试用或正式发布。

### 第一轮真实模型证据 R-ERP-20261020-01：技术流程跑通，语义未通过

执行入口为 `scripts/verify-erp-real.mjs`，需显式启用真实验收开关，默认测试不会自动调用付费模型。私有证据位于 `.office-data/erp-real-acceptance-ZtEA02/acceptance.json`，该目录不进入 Git。

记录显示：模型 `qwen3.7-plus-2026-05-26`；八类业务共九次运行（领用、归还各一次）；两个独立虚拟岗位、38 次工具调用；九张业务单最终均为 `completed`；采购分批收货、销售分批发货后，经借还与盘点，库存为 6，未归还数量为 1。项目任务由不同真实测试账号验收，形成一份贡献快照。报告下载内容已由验收脚本核对。

这些是真实模型和真实软件执行记录，账号、项目、审批、收发凭证及库存均为明确标记的隔离测试资料，不代表公司实际到货、发货或客户签收。

后续独立 Agent 内容复核发现第一轮文字存在业务语义错误：领用方案误写采购，盘点说明出现无依据归因，周报错误声称无需审批。数据库仍按规定执行两级审批，但这些文字会误导使用者，因此第一轮不能判为八链内容质量通过。保留原始证据，修正岗位指令与语义检查后另存新结果，不覆盖第一轮记录。

### 修正与最终轮证据 R-ERP-20261020-02：本组样本技术与语义通过

候选版本 `v3.0.0`。中间证据 `.office-data/erp-real-acceptance-D373Tf/` 记录独立复核拒绝、运行失败、工作单保留草稿，没有送审。最终证据 `.office-data/erp-real-acceptance-yXlSDn/` 使用同一真实模型 `qwen3.7-plus-2026-05-26` 完成八类型、九次运行、18 个岗位任务及 38 次工具调用，并经独立 Agent 逐链对照输入、计算、来源和实际 SQLite 记录复核通过。

现货领用不再误写采购；盘盈原因全部列为待确认；周报明确需要两级审批；交付验收逐项引用相符的业务单和库存流水；岗位准备识别真实岗位不一致及资料缺口。审批由测试脚本通过不同员工测试账号执行，不是实际公司审批，也不是专业团队签核。脱敏结论、证据对照和边界见 [ACCEPTANCE.md](ACCEPTANCE.md)。

首轮及最终样本的采购各抓取了 8 个候选来源，均没有取得 `priced` 状态的有效整机报价；结果为待询价或多个价格候选。该证据证明真实联网和缺价处理路径，不证明取得了合格报价。商业采购试用还须补足可用报价的正向样本、配置与税费核对。

## 3 已识别差异与关闭条件

- **G01 停用后接替**：已补项目维护和任务转交后端；须补完在岗员工校验、可操作界面与停用后接续验收，不能只证明账号被停用。
- **G02 金额可见范围**：首期为授权项目成员共享项目业务金额与公司共用产品参考价；不宣称已实现按字段隐藏项目成本。商业试用前由业务与财务确认该范围，PRD 与接口保持一致。
- **G03 修订员工关联**：创建和修订资源／岗位准备单均须核对真实在岗账号；完成不存在、停用、跨项目及来源错误的接口测试后关闭。
- **G04 盘点、领用与贡献补充**：盘点原因、领用用途、准备单来源及新事实指标不得只在文档中出现；服务端、表单、报告和自动测试逐项回归后关闭。
