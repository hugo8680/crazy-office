# v4 · 工作区拆分与 Go 迁移

本次只调整工程边界与服务端实现，保留现有办公室设计及业务入口。工作区根下的两个项目各自构建、测试和发布，通过同域 `/api` 协作。

## 工程边界

`client/src` 保存原有静态客户端，2D／3D、人物、动作、审批弹窗、ERP 工作台和文案继续沿用。构建直接复制源文件并生成 SHA-256 清单，避免迁移时改变已有页面。Vite 仅用于本地开发与 API 转发；生产由 Nginx 提供静态文件。

`server/cmd/office` 启动 Go API。身份和口令、会话、角色及范围、SQLite 台账、审批、任务、库存、报表、真实模型调用、工具、协作运行、自动派工和 SSE 均为 Go 实现。生产运行只需要 Go 二进制、公开示例和私有配置，不调用旧 Node／Python 服务。

旧源码对照副本已移到工作区以外；旧部署记录保存在 `docs/legacy-deploy`，旧接口说明保存在 `docs/LEGACY-CONTRACT.md`。这些历史记录不作为 v4 启动入口。

## 兼容要求

- 保留现有 API 路径、JSON 字段、会话签名与 Node scrypt 口令格式；旧账号和有效会话继续使用。
- 保留 SQLite 表及事务约束、角色与项目范围、两名不同真人审批和禁止自批、版本检查与幂等键。
- 保留分批收发、原借用单归还、盘点快照校验和北京时间事实周报。金额按整数分计算，参考价与实际报价分别记录。
- 保留实验室历史运行、旧绝对产物路径的受控迁移、报告、CSV／XLSX／SQLite、ZIP 下载与事件流。文件仍须在任务产物登记表内，解析后不能逃出任务目录。
- 模型调用失败必须显示真实失败。独立复核不能代替整数金额及业务状态校验；不把工具测试替身当成真实模型验收。
- 大输入的工具保留全文，模型预览明确标注范围；禁止静默丢弃损坏数据后回报导入成功。

## 发布边界

生产域名继续为 `office.laisengou.com`。静态文件部署到 `client/releases`，Go 发布到 `server/releases`；各自的 `current` 独立切换。持久数据继续使用原 `data`，私有 `office.env` 沿用，不进入任何发布包。Go 只监听 `127.0.0.1:8080`，由 Nginx 提供 HTTPS。

迁移前保存自动派工配置、等待活动任务、备份业务库及全部历史文件，在隔离副本中验证旧数据。切换时停止旧 `office-lab`，再启动 `office-api`，避免两个调度器共写。旧服务、旧站点和旧发布目录保留为回退点。后续独立发布仍须备份、等待任务、验收后恢复自动派工。

## 验收记录

自动测试、实际模型样本与生产切换证据记录在本目录的 `MIGRATION-ACCEPTANCE-20261020.md`。私有运行原文、邀请凭证、账号、密钥和完整备份仅留私有目录。首次业务试用仍须由参与员工确认流程与职责，不以隔离测试的审批账号冒充公司实际审批。

容器入口已提供；本次服务器使用原生二进制与 systemd，未将未执行的 Docker 启动验收写为通过。
