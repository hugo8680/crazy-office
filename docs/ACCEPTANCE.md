# 疯狂办公室 ERP：v3.0.0 候选验收记录

记录日期：2026 年 10 月 20 日，北京时间。需求基线见 [PRD](PRD.md)，开发与发布状态见 [实施追踪](IMPLEMENTATION.md)。

**结论：本组隔离样本的真实模型技术链路与业务语义复核通过。** 本记录只覆盖所列代码路径和测试资料，不代表实际公司业务获批、所有输入均正确、正式商业签核或生产验收通过。

## 范围与方法

- 候选版本：`v3.0.0`。最终发布版本仍须完成冻结代码后的完整回归与发布检查。
- 实际模型：`qwen3.7-plus-2026-05-26`。
- 八种业务类型：项目立项、交付验收、采购、销售发货、库存盘点、物品领用归还、项目周报、岗位资源准备。
- 最终样本：9 次实际协作、18 个虚拟岗位任务、38 次模型决策和 38 次工具调用。领用、归还分别执行，因此运行数多于业务类型数。
- 每次由业务整理与独立复核两个岗位分别读取工作资料；独立复核须明确返回 `passed`。岗位交付与复核不代替员工审批。
- 复核对照原始输入、工具计算、网页抓取证据、实际 SQLite 业务单与库存流水，并检查审批前后的时间顺序。
- 内容复核为独立 Agent 审查，不是公司业务负责人或专业评审团队的正式签核。

验收使用明确标记的隔离账号、项目、产品、凭证和数量。**审批由测试脚本使用不同员工测试账号调用审批接口，验证身份、岗位、顺序和禁止自批规则；不是实际员工对公司真实事项作出审批。** 收发货和验收同样是隔离台账操作，不代表实际到货、发货或客户签收。

## 三阶段证据对照

### 首轮：技术通过，内容未通过

私有证据目录：`.office-data/erp-real-acceptance-ZtEA02/`。

真实模型完成了两岗位、工具调用、测试账号审批、库存事务和报告生成。独立内容复核发现：领用误写为采购；盘点对差异作出无依据归因；周报错误声称无需真人审批；交付验收未逐项核对原始标准；岗位准备部分核验断言缺少依据。

因此，本轮只能记为技术流程跑通，不能记为八条链的语义验收通过。原始记录保留，不用后续结果覆盖。

### 中间轮：独立复核拒绝，保留草稿

私有证据目录：`.office-data/erp-real-acceptance-D373Tf/`。

独立复核未通过，实际运行标记失败，工作单保留草稿，没有继续送审。这一记录证明拒绝路径真实发生，不能将其计为成功运行，也不能据此证明所有错误均能被识别。

### 最终轮：本组样本技术与语义通过

私有证据目录：`.office-data/erp-real-acceptance-yXlSDn/`。

九次协作均完成真实工具调用，并由独立岗位明确复核通过。逐项对照确认：

- **项目立项**：整理目标、范围、计划日期、成员与审批链，后续报价和配置事项保留为后续阶段缺口，没有假称本阶段已完成采购。
- **采购**：执行真实公开检索与抓取，区分工作单参考价与供应商报价，明确记录未取得有效标价和待询价事项。
- **销售发货**：申请数量、库存及金额与工具核算一致，准确说明方案和批准不等于实际发货，出库仍由仓管登记。
- **领用**：准确识别现有库存足够，准备领用审批和出库要求，不再把领用强制改为采购。
- **归还**：核对原领用单、同员工借用余额及归还上限；实际归还入库仍须员工办理。
- **盘点**：账面、实盘、差异计算一致，差异原因保留待确认，没有把已入账归还再次解释为盘盈来源。报告分开标明实盘参考额与差异参考额。
- **交付验收**：逐条核对原始收货、发货、领用和归还标准，引用的业务单与流水编号及数量均能在 SQLite 中对应；没有把隔离凭证冒充客户签字。
- **项目周报**：引用已由另一账号验收的任务及业务事实，保留提交、验收与业务参与的不同口径，准确说明周报本身仍须两级审批，不产生评分或收入归属。
- **岗位资源准备**：识别申请岗位与在册岗位不一致，准确引用借用余额，并保留权限清单和使用文档缺口，没有假称外部账号或权限已经开通。

最终库存流水、未归还余额和贡献快照核对一致。各工作单的两级测试账号审批时间晚于 Agent 处理完成时间，审批及库存结果来自业务接口与 SQLite 事务，不来自模型自述。

## 采购证据边界

本组采购实际抓取 **8 个候选来源，0 个有效明确报价**。候选为待询价或多价格片段，不能作为目标配置的合格成交报价。工作单中的单价和总额属于申请或参考价格，模型与报告均未将其称为已核实供应商报价。

这证明了联网、取证、缺价识别与后续询价路径；不证明取得了可用报价、完成全网比价、供应商真实性核定、采购成交或实际付款。商业采购试用仍须补充配置、币种、税费、运输、保修和有效来源均可核对的正向报价样本。
