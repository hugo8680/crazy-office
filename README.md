# 疯狂办公室

全屏卡通办公室，十一位带虚拟胸牌的虚拟员工通过真实模型、岗位工具和证据交接完成办公任务。真实员工按老板、财务、IT、业务、采购、投资和人事职能展示，由使用者操作资料提交、业务审阅与审批；背景工位人物保留办公室氛围。等待真人审批时，负责人办公室持续高亮，并自动打开大屏人物对话框。

## 服务器与自动派工

生产入口为 [office.laisengou.com](https://office.laisengou.com/)，公网访问需登录。服务器直接连接阿里云百炼的 `qwen3.7-plus-2026-05-26`，无需服务器代理或个人 Codex 登录。API 密钥只在私有服务端配置中保存；本机开发仍可复用 Codex，已安装的 Qwen 4B 本地模型可手动选用。

底部“更多操作 → 自动派工”可设置 3–5 分钟随机间隔和任务范围；派工在服务器运行，关闭浏览器也会继续。正在执行或等待真人审批时暂停新任务；停用只停止未来派发。公司背景来自用户提供的主体名称与有来源的官网信息，内部计划、采购筛选上限与数据库测试样本明确标注为草案或假设。缺真实财务、入职、投资和网络资料时不自动执行这些场景。

服务、配置、证书续期、更新与回滚见 [部署说明](deploy/README.md)。工作资料与密钥保存在代码目录之外，不能上传到 Git。

## 运行当前版本

需要 Node.js 20+、Python 3.9+。模型优先复用本机已登录的 Codex CLI。

在这台已配置的 Mac 上，可双击 `启动疯狂办公室.command`；已有服务时会打开页面，不会重复占用端口。服务运行期间保持终端窗口打开。新电脑先安装依赖并登录，再按下面命令启动。

```sh
npm install
codex login
mkdir -p .office-data
cp config/provider.example.json .office-data/provider.json
npm run dev
```

访问 `http://localhost:4173/`，点击左上角模型状态，执行“检查模型连接”。确认真实请求成功后，选择任务、导入资料并一键派工。

模型配置保存在本项目 `.office-data/provider.json`，不修改用户全局 Codex 设置，也不保存密钥：

```json
{"provider":"codex","model":"gpt-6-luna"}
```

本机已经使用上述模型和现有 ChatGPT 登录实测成功。会占用账户的 Codex 使用额度。若某个账户不支持该模型，在本文件填入该账户已授权模型。连接会优先使用既有 `HTTPS_PROXY` / `HTTP_PROXY`，macOS 上也会读取现有系统代理，仅对本应用生效，不更改全局设置。

可选 `OFFICE_PROVIDER=openai`、`OPENAI_API_KEY`、`OFFICE_MODEL` 使用 OpenAI Responses API，密钥只从服务端环境读取；也可使用 `OFFICE_PROVIDER=ollama`、`OFFICE_MODEL=<已安装模型>` 连接本机 Ollama，不会自动下载模型。API 和本地模型都不会静默替代 Codex，失败时保留实际错误。

### 可选的百炼正式 API

百炼通过私有服务端环境显式配置 `OFFICE_PROVIDER=dashscope`、`DASHSCOPE_API_KEY` 和 `OFFICE_MODEL=qwen3.7-plus-2026-05-26`，应用不会静默切换模型。北京地域默认直连 `https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions`；`OFFICE_DASHSCOPE_URL` 可填同地域官方业务空间专属兼容接口。

适配使用原生 Chat Function Calling，模型选择真实岗位工具及参数，服务器仍执行授权、参数校验和实际工具。单轮多个调用全部拒绝，不丢弃后继续执行；历史调用与真实回执配对，孤立纠错仅作为数据。请求超过700 KiB时明确拒绝，不截断资料。工具请求的摘要标为 `tool_call_metadata`，不冒充已执行结果；最终交接正文来自模型内容。`enable_thinking=false`、`parallel_tool_calls=false`，未依赖 Responses 的 `text.format` 兼容假设。

未配置密钥时连接状态为未就绪，不发起模型请求。启用后的启动探测、手动连接检查及自动恢复探测均可能计费；正式切换需用同一地域密钥，并重新完成业务验收。按量价格与额度以 [百炼官方计费](https://help.aliyun.com/zh/model-studio/model-pricing) 和账户控制台为准，不预设免费额度。密钥创建参考 [官方 API Key 说明](https://help.aliyun.com/en/model-studio/get-api-key)。

## 局域网访问

默认监听 `0.0.0.0:4173`，同一网络的设备可使用启动时打印的 `Office LAN` IP 地址。地址以当前网卡为准，DHCP 变化后重新查询即可；IP 中的零段不代表它无效，需要结合子网掩码判断。

只有系统提供有效计算机名时才打印 `.local` 候选地址；它还需要设备支持 mDNS，不能保证跨 VLAN 或访客网络可用。公网部署统一使用 `https://office.laisengou.com/`，后端仅绑定服务器回环接口，由 Nginx 提供 HTTPS。
## 七个场景

- 员工入职登记：为公司已经确认录用的员工办理登记。人事专员整理资料，独立核查与办公资源整理并行，由真实人事负责人通过大屏对话框确认或退回；批准后以原子事务写入本地 SQLite 员工名册，并生成本次登记表、核查结果、资源待办及交付报告。设备、账号与权限均标记待办理，不伪称已开通。示例和真实名册分别存储，同工号同资料可重复办理，冲突工号或邮箱禁止覆盖。

- 投前尽职调查：投资研究员梳理项目方说法、真实检索公开来源，财务尽调师核算上传数据，独立风险审查员逐字核查引文和关键缺口，协调人生成老板决策简报。老板通过大屏对话框选择继续尽调或暂缓项目，决定只记录研究方向，不签约、不投资、不打款。输出来源清单、证据表、财务核算、风险审查、补材料清单、简报和老板审阅记录。

- 年度财务汇报：导入逐月数据到真实 SQLite，以整数分计算收入、毛利、经营利润、净利润、现金与同比；财务分析与独立审校并行，最后生成 Excel、CSV、HTML 和中文报告。页面提供示例模板。输入不足以支持法定财务三表时不伪造资产负债表。
- 服务器采购比价：真实 HTTP 检索并抓取公开供应商页面，保留 URL、时间、币种、产品类型、标价和配置证据。配置、税费、币种与预算分别核对，缺价或被网站阻止时输出待询价。范围限于本次查到的候选，无法承诺穷尽互联网，也不自动采购或付款。
- DDoS 诊断与隔离修复：分析用户提供的请求日志，由模型选择封禁/限速方案，真人批准后写入本次隔离策略并真实重放验证正常请求、恶意请求和误伤率，交付 JSON 与 nginx 配置。不会攻击外网或修改生产设备。
- 业务数据库搭建：业务分析师提取需求，工程师设计可执行 SQLite DDL，数据工程师真实建库导入，审校员工运行可回滚的约束正反例和查询。下载数据库、SQL、设计与测试结果。 自动数据库原型采用合同范围验收，工具独立复跑全部显式 SQL 合同，不请求模型重复生成测试；手工任务仍可提供附加用例，合同通过不代表全覆盖。
- 客户需求与交付计划：从客户原文提取有来源的需求与验收标准，拆工作包和依赖，工具计算排期/人日/预算，独立审校覆盖率，交付规格、计划、预算和验收清单。不发送客户消息，不作合同承诺。

示例资料必须主动选择，不会替换缺失或有误的真实资料。财务模板支持英文及常见中文列名，要求两年各 12 个月，字段是 `year,month,revenue,cost,operating_expense,other_income,tax,opening_cash,cash_in,cash_out,closing_cash`，金额单位元。缺月、重复和现金不平衡会报错。

数据库需求正文最多 24000 字符；交付计划的需求与补充文本合计最多 24000 字符，超出时要求拆分任务，不会静默截断后半需求。财务、日志和数据库导入文件由实际工具读取完整内容。

投前研究的项目名称、简介及补充 TXT/JSON/CSV 合计最多 24000 字符；可另提供最多 240000 字符的财务 JSON/CSV。财务行字段为 `period,revenue,gross_profit,net_profit,cash,monthly_burn,debt`，金额单位元，`revenue` 必填，其余未知可留空；按上传顺序比较最后两期，期间与币种是否可比仍需核对。绝对值超过一万亿元的 JSON 数字金额会拒绝，须使用金额字符串或 CSV，以免 JSON 数字解析先丢失分精度；金额以整数分核算，并保留精确字符串。不自动读取 PDF、付费企业库或绕过网站验证码。项目自述、网页说法、计算一致与独立核实分开呈现，未查到不等于没有风险。

入职表单仅收集工号、姓名、部门、岗位、入职日期、可选工作邮箱、直属负责人和办公资源需求。必须主动确认“公司已确认录用，仅办理入职登记”。不收集身份证、银行卡、薪资或健康资料，不作录用筛选。姓名、工号、邮箱、直属负责人和入职日期只在本地登记与审批资料中使用，模型接收匿名员工引用、字段是否填写及部门、岗位、资源需求。资源需求请仅填写工作需要。共享名册位于 `.office-data/hr/`，示例名册与真实员工名册分别存储；每次任务仅导出本人的登记表，不导出整份共享名册。

投前初步研究围绕主体、业务、股权、财务、资质、技术、交易条款和退出安排建立证据与待核查事项。方法参考[财政部关于直接股权投资的公开文件](https://www.mof.gov.cn/gkml/caizhengwengao/wg2014/wg201407/201502/t20150204_1188179.htm)中列出的尽调与投资分析维度，不把特定国有机构规则当作所有用户的法律义务。最终资金决策仍需结合线下资料、审计、法律核验和实际交易条款。

## 实际协作机制

办公室中的员工分为两类：带青绿色“虚拟”胸牌的模型员工，以及带暖色“真实员工”名牌的使用者职能角色。真实员工包括你（老板）、财务负责人、IT 负责人、业务负责人、采购负责人、投资负责人和人事负责人；点击他们可以提交相应资料、查看交付，或进入当前待办审批。职能角色由使用者操作，不表示已有七名同事登录，也不会由模型自动替真人发言、批准或确认业务验收。

人物交付根据实际执行事件展示：提交资料后向执行岗位交接，岗位完成后向下游交付证据，申请审批时向指定真实负责人递交方案，最终文件生成后向对应真实员工交付。小人沿办公室通道和门口移动，携带文件，到达后显示交付摘要。刷新或切换历史记录只恢复状态，不重新演完整段历史；减少动态效果时保留明确的交付反馈。场景动作不延缓服务器执行，也不能替代工具成功回执或真人审批。

每名虚拟员工有自己的职责提示、上下文和白名单工具。模型根据目标与同事交付的证据，输出下一步工具调用指令，服务器执行后将真实结果传回；不是定时器推进或硬编码的成功动画。角色拥有独立工作状态，同一角色同时只处理一项工作，不同角色可并行。岗位任务之间按已完成的前置结果交接。

当前总流程采用可检验的任务图，岗位内的工具参数、方案与最终报告由模型生成。它不是任意目标的完全自治系统。模型不能调用宿主 shell、改生产设备或绕过岗位工具；网页和文档内容都作为不可信资料处理。界面展示公开行动摘要和工具证据，不展示模型私有推理。

状态、原始资料与文件保存在 `.office-data/<任务ID>/`（Git 忽略）。刷新可恢复进行中的任务，有序停机取消活跃任务并写明服务停止；异常中断后重启明确标为失败，可重试。状态文件原子写入，失败和中断记录重启后仍可下载。模型参数格式错误最多反馈纠正两次，权限校验不会放宽。取消、失败和审批拒绝都会保留已生成的证据。只有实际生成文件且完成岗位任务才能标记流程完成；流程结束也不代表所有业务验收已经通过，应查看各项结果。

# 第一版：疯狂网络实验室

一个全屏卡通办公室网络抢修网页。整个办公室就是网络拓扑，角色、设备、配置、日志和审批均通过场景内动作打开，用来演示有不同技能的模拟 Agent 如何通过证据交接、依赖任务和并行执行恢复业务。

## 本地运行

需要 Node.js 20 或更新版本，无需安装第三方依赖。

```sh
npm run dev
```

访问 `http://localhost:4173`。可用 `PORT=4180 npm run dev` 修改端口。

## 演练流程

1. 点底部“开始一次抢修”选择 DDoS、机房断电或核心交换机故障；也可点击互联网、UPS 或核心交换机打开故障动作。
2. 确认系统按技能推荐的小队，直接开始。可选勾选或取消角色，点击小人配置名称、职责、工具与协作对象。配置保存在本机；关闭必需工具或交接权限会在故障注入前明确提示。
3. 观察角色移动到设备工作、向其他角色交接证据。每项工作完成后，小人旁弹出“任务、行动、结果”。提示按事件排队，打开操作面板时暂停展示计时，不会被后来的工作覆盖。
4. 审批在提交方案的角色旁出现。财务与总经理同时入队才能申请外部预算；否则仅可确认本地方案，不能通过界面或直接调用绕过。
5. 点击小人查看他做了什么，点击设备查看局部记录。底部“记录”和“更多动作”可打开全局日志、共享任务及档案。
6. 完成后导出 JSON 报告；最近 12 次完成的演练和角色配置保存在当前浏览器的本机存储中。

支持空白拖动平移、滚轮缩放、暂停、继续、单步推进 5 秒、1/2/4 倍速和拓扑连线开关。窄窗口默认显示可拖动的近景，“适应画面”按钮可切换全景。空格键暂停或继续，Esc 关闭浮层；角色和设备均支持键盘操作。

## 仿真边界

当前版本是**本地规则驱动的多角色技能协作仿真**。没有调用真实大模型，没有连接生产网络，没有真实采购或财务支出。每个角色维护职责、工具权限、可交接对象、任务、动作、结果和设备位置；所选角色的技能会改变任务分配与串并行关系，未派遣角色不会接任务。任务按前置结果调度，同一角色不会同时执行多个任务。

职责文本保存为角色行动上下文；当前固定场景使用技能和权限规则执行，修改自然语言职责不会让模型实时自由规划。角色名称变化不能伪造其他角色的独有工具。财务和总经理属于可选管理协作，业务用户验收未入队时会明确记录尚缺用户侧确认。

网络使用 12 个逻辑节点和设备/业务依赖图。80 个模拟用户分布于办公、会议、管理、接待和财务区域。可用率按终端状态加权；延迟、丢包与费用为仿真数据，不能用作生产网络测量。

完整恢复与本地降级结果分别记录。断电降级会暂停会议室供电，交换机降级会限制会议带宽，DDoS 降级会保留出口拥塞风险。报告的串行工时为同一组模拟任务时长之和，不能解释为真实生产效率提升。

真实模型接入可从 `dist/simulation.js` 的角色调度、工具执行和证据交接接口扩展，需保留设备依赖、行动权限与独立验收。
