# 疯狂办公室工作区

工作区包含两个独立项目：

- `client`：办公室客户端，负责 2D／3D 场景、人物、动画、表单和交互。独立使用 npm 开发、检查、测试、构建和发布。
- `server`：Go API，负责登录与角色、业务台账、真实模型处理、工具、审批和业务结果。独立使用 Go 开发、测试、构建和发布。

打开 `疯狂办公室.code-workspace` 可同时加载两个项目。两边通过同域 `/api` 协作，不互相导入源码或依赖对方的构建工具。

## 本地运行

服务端，在 `server`：

```sh
go run ./cmd/office
```

客户端，在另一个终端的 `client`：

```sh
npm ci
npm run dev
```

访问 `http://localhost:4173/`，登录在办公室内完成，无需访问独立登录页。客户端开发端口为 4173，Go API 为 `127.0.0.1:8080`。模型配置和数据只在 `server` 中维护，详见两个项目各自的 README。原有两个 `.command` 启动入口也分别放在各自项目中。

## 使用与结果

办公室底栏提供工作台、项目、单据、进销存、人员和报表。新建单据填写实际资料并提交后，在同一单据中读取办理内容、金额数量、缺项和当前审批。业务确认后，收发货进入库存流水，已验收任务保留交付文字及凭证，工作记录进入报表。没有独立产物入口，也不在页面展示模型、工具或 Agent 的执行日志。

账户、2D／3D、缩放、旋转及全屏都从底栏操作；工作台展开不禁用底栏。员工邀请由管理员在人员管理中创建，员工通过 `/join#token=...` 设置密码后在同一办公室登录。邀请和密码不进入浏览器存储。

## 验证与发布

客户端运行 `npm run check && npm test && npm run build`，发布 `client/dist/`。服务端运行 `make check && make test && make release`，发布 Go 二进制和服务端示例配置。双方各自带有部署、回滚脚本和容器构建入口，分别见 [客户端发布](client/README.md) 与 [服务端部署](server/deploy/README.md)。

生产入口为 `https://office.laisengou.com/`。Nginx 提供客户端静态页面并反代 `/api`；Go API 只监听服务器回环地址。客户端更新不重启 Go，服务端更新不替换客户端；跨接口变更先完成双方兼容检查再切换。每次开发完成并通过测试后部署，发布前备份、完成活动任务，发布后验证并保留回滚点。

本轮候选为 v4.1，新增界面要求、真实功能边界及待完成的 TokenDance 模型与部署验收见 [v4.1 验收清单](server/docs/ERP-UI-ACCEPTANCE-v4.1-20261020.md)。开发测试通过不等于新模型或生产发布已通过，发布状态以该清单中的实测记录为准。

产品需求仍以 [PRD](server/docs/PRD.md) 为基线；本轮界面增量以 v4.1 清单覆盖旧登录、实验室入口及执行细节呈现约定。架构、兼容边界及迁移验收见 [Go 迁移说明](server/docs/GO-MIGRATION.md)。
