# 疯狂办公室 · Client

办公室客户端。保留现有 2D／3D 场景、人物、动效、场景内工作台、账号及业务结果，通过同域 `/api` 调用 Go 服务。这里不保存员工身份库、业务台账、模型密钥或任务执行逻辑。

## 开发

需要 Node.js 20.19+ 或 22.12+。本机已使用 Node.js 20.20 完成构建和测试。

```sh
npm ci
npm run dev
```

打开 `http://localhost:4173/`。开发服务器默认将 `/api` 转发到 `http://127.0.0.1:8080`；启动 API 的方法见 `../server/README.md`。可用 `OFFICE_API_TARGET` 覆盖目标：

```sh
OFFICE_API_TARGET=http://127.0.0.1:8080 npm run dev
```

登录、个人资料和修改密码都在办公室场景内办理，底部账户按钮打开同层对话框。员工邀请和密码设置链接 `/join#token=...` 也返回办公室；邀请令牌只放 URL fragment，客户端启动时立即清除，不进入访问日志、DOM 或浏览器存储。旧 `/login` 书签重定向至 `/`。

## 页面操作

- “单据”选择业务类型并填写；提交后留在当前单据，结果完成后原位显示。
- “工作台”集中处理本人任务及有权审批的单据；审批和实际收发货是不同动作，库存只随真实办理更新。
- “项目”查看项目及任务，已验收任务显示实际交付与凭证；“人员”办理邀请、权限和员工当前工作。
- “进销存”切换库存、产品、流水及领用；“报表”直接阅读项目完成情况、已确认工作记录和进销存数据。
- 左上角图标切换 2D／3D，右上角进入全屏。左键拖动平移，右键拖动旋转，中键也可平移；滚轮与触摸板双指上下滑动均围绕指针缩放，触摸板捏合也缩放，不根据滚动幅度切换为平移。触屏单指平移，双指缩放、平移及转向。Home 或底栏办公室图标恢复全景。
- 登录后，WASD／方向键按当前镜头方向行走，碰到家具或墙体会停下或沿边滑动；穿过门洞进入部门。松键同步位置；打开窗口、输入文字、失焦或切到后台立即停键。窗口关闭不会自行恢复旧按键。
- 悬浮任一部门，其地板与完整轮廓高亮。向内缩放进入该部门，向外缩小退回园区；12 个部门使用同一规则。单击或双击部门标题、人物、姓名与桌面均不控制镜头。
- 点击可通行空地显示目的地并行走，途中点击新地点会替换目标；拖动结束不会当成行走指令。家具不透传点击；同部门内沿空地就近行走，跨部门经过门洞与公共通道，实际进门后再平滑聚焦。手动调整镜头只取消自动聚焦，人物继续行走。
- 默认斜俯角约 31°。自动构图平缓起停，滚轮短时跟随，拖动即时响应。2D／3D 复用已构建场景，切换前准备首帧并同步最新观察中心、比例和人物位置；保留 3D 的旋转角度。关闭业务窗口和人物浮层保留关闭前镜头。
- 点击同事或姓名打开个人名片，点击桌面选择工位；工位按登录人的实际部门权限与实时占用确认。账户内选择六套搭配并保存，衣着跟随账号，刷新或重新登录后保留。本人定位入口在账户姓名旁。
- Esc 每次只处理一层：关闭当前窗口；没有窗口时停止当前行程；没有行程时退回全景。按住 Esc 不会连续退出多层。输入框、业务窗口与地图有独立输入边界。
- 园区总览用代表工位控制密度；进入部门后启用完整人员和工位。AI 数据算法部由 21 个代表工位切换为 206 个完整工位，继续缩放、平移、旋转不会收回人员，返回总览后再恢复代表。工位、姓名和服务端坐标使用同一份完整组织名册。
- 部门悬浮、进入退出及本人脚步有轻量音效。音效在用户首次操作后启用，底栏扬声器图标可静音；无背景音乐，隐藏页面停止播放。

工作台不重复模块导航，不禁用底栏。单据结果和报表在业务页面内阅读，HTML／CSV 只作为次要导出。模型状态、岗位配置、工具与执行日志不属于本轮页面内容。旧实验室组件保留历史兼容与测试用途，当前 `office.js` 不挂载实验室入口。

本轮功能与发布门槛见 [v4.1 验收清单](../server/docs/ERP-UI-ACCEPTANCE-v4.1-20261020.md)。真实公司资料由授权员工录入，空台账不会生成示例经营数据。

## 检查、测试与构建

```sh
npm run check
npm test
npm run build
```

`src/` 是源码，`tests/` 只负责客户端和交互测试，`dist/` 是发布目录。构建保留场景资源，输出 `asset-manifest.json` 记录文件摘要。`npm run preview` 在 4173 端口预览构建，并使用同样的 `/api` 代理。

## 独立部署

生产静态目录：`/opt/office.laisengou.com/client/current`。API 进程和数据由服务端独立管理，客户端发布不重启 Go，不改公司数据。

1. 本地运行检查、测试与构建，将 `dist/` 传到服务器临时目录。
2. 校验 `asset-manifest.json` 对应的文件摘要。
3. 服务器执行 `deploy/release.sh <已验证的dist目录> <版本号>`。脚本使用客户端发布锁，在暂存目录完成复制后原子切换 `current`，已有版本不覆盖。服务器需提供 `flock`、GNU coreutils 和 Nginx；不会调用 Node。
4. 验证匿名访问显示办公室和场景内登录、退出与过期后原地重新登录、2D／3D、工作台、邀请入口，以及单据结果、审批和报表。事件流兼容性另外按服务端接口检查，不作为当前页面入口。

首次由旧版一体化服务迁移时，按 `../server/deploy/README.md` 操作。Nginx 站点为 `deploy/office.nginx.conf`，公共 locations 文件放在 `/opt/office.laisengou.com/client/nginx.locations.conf`。先运行 `nginx -t`，再切换该域名配置；其他站点保持原样。

部署规则：

- 办公室与静态资源提供公开的场景外壳；`/login` 与 `/login.html` 重定向 `/`；`/join` 与 `/join.html` 提供同一办公室场景。场景外壳没有公司业务数据。
- `/api` 原样反代 `127.0.0.1:8080`，JSON 权限由 Go 校验，不能以静态页鉴权代替 API 鉴权。
- SSE 关闭代理缓冲与缓存，读取超时 300 秒。
- `.mjs` 使用 JavaScript MIME 类型；CSS、图片等沿用标准 MIME 配置。
- 静态目录只放 `dist/` 内容，不放工作区根目录、环境文件或运行数据。

`src/session-ui.js` 的 `mountSession` 接受原始 fetch 语义的 `requestRaw`（返回 Response）和身份事件回调，提供 `ready`、`open`、`close`、`requireLogin`、`refresh`、`signOut`、`session` 及 `destroy`。所有请求使用同源 Cookie，不在浏览器保存口令或令牌。后台返回 401 时调用 `requireLogin` 清理当前业务视图并原地重新登录。

回滚只切客户端版本：

```sh
./deploy/rollback.sh <已有客户端版本号>
```

回滚后检查与当前 API 的接口兼容性。涉及接口变更的发布须先通过双方契约测试。

## 容器

```sh
docker build -t crazy-office-client:4.1.0-candidate .
```

运行镜像时提供 `OFFICE_API_UPSTREAM`，默认 `office-server:8080`。该名字须能在容器网络内解析。镜像仅含静态资源与 Nginx，监听 8080；对外生产访问仍通过 HTTPS。模型和登录密钥只交给服务端容器。

容器配置提供独立打包入口；正式切换前还需在目标容器网络中验证域名、HTTPS、会话和事件流。本次环境若没有 Docker daemon，不能将 Dockerfile 语法准备写成容器运行验收已完成。


## 4.1.2 人物悬浮问候

- 真实在线员工：快乐表情、一次招手，按北京时间显示早上／中午／下午问候，夜间使用晚上问候。
- 虚拟员工：机器人笑脸和“随时待命！”。2D 与 3D 共用 `person-greeting.mjs` 时间规则。
- 鼠标离开、失焦、拖动、隐藏页面或移除人物时清除问候。问候不发起业务请求；行走和交接不被招手覆盖，减少动态效果时保留静态表情文字。

本次仅发布客户端。语法检查、202 项客户端测试与 37 项资源构建通过；本机浏览器已实际核对 2D／3D 的两类人物问候和离开清理。Go 服务及业务台账保持原版本。


## 4.1.3 对话框设计

- 业务工作台、表单、审批与验收、账户与设置窗口使用统一的颜色、圆角、标题徽章、字段分组和操作层级。共享变量放在 `src/dialog-system.css`。
- 明细表、状态、办理意见、成功与错误反馈按同一套视觉规则展示；小型视图菜单、收件提示和员工问候气泡同步精修。不使用阴影或单侧强调条。
- 保留现有业务请求、权限、草稿与刷新逻辑；沿用原生账户弹窗焦点和 Escape、减少动态效果设置及窄屏滚动。审批、退回和密码设置链接的操作条件保持不变。

本次仅发布客户端，Go 服务与业务数据保持原版本。


## 4.1.4 画布清晰度与视图控件

- 3D 按高分屏密度绘制，常见 Retina 桌面支持 DPR 2；保留 900 万像素及 GPU 尺寸上限。窗口、全屏和屏幕密度变化会同步画布缓冲，尺寸不变时不重新分配。
- 场景内滚轮统一覆盖画布、员工和房间标签；Safari 原生缩放手势映射至镜头，避免把整个页面放大。
- 导航、视角图标、视图菜单和提示共用独立控件层。VisualViewport 缩放、偏移或软键盘改变可视区域时，控件留在可见区域；业务内容仍可按浏览器规则缩放。无 VisualViewport 的环境保留 CSS 布局。
- 控件监听通过单帧合并，没有持续空闲渲染；销毁清理全部监听和排队帧。本次仅发布客户端。


## 4.1.5 刷新全景与操作坐标

- 办公室与操作栏按同一可视区域定位。浏览器保留原生捏合缩放和偏移时，刷新、2D/3D 切换仍显示完整办公室；只保存视角偏好，不保存局部镜头。窄屏 2D 不再强制 850px 画布。
- 3D 渲染、相机和 HTML 标签使用布局尺寸；鼠标、双指输入换算至同一坐标，射线按实际显示区域归一，避免画面、点选与手势错位。房间和员工上的右键拖动不弹浏览器菜单。
- 2D 滚轮保留原操作习惯，改用温和的相对倍率与稳定锚点；补齐双指及 Safari 捏合。左上角独立提供“恢复全景”图标。
- 业务窗口和原生账户对话框按实际可视边界定位并保留内部滚动、浏览器正文缩放；业务窗口预留导航的间距按屏幕比例换算。现有权限、草稿、表单提交与业务请求不变。

本次仅发布客户端，服务器进程与持久业务数据不变。


## 4.1.6 UI 基础与交互稳定性

- 生产入口只加载统一 foundation 与作用域内的组件样式；旧实验室 CSS 不再进入 ERP。字体、主题色、控件规格集中维护，组件职责有契约测试。扩展约定见 [UI 开发契约](docs/ui-foundation.md)。
- 一个视口控制器同步场景、业务和操作层。业务窗口与原生账户对话框使用相同屏幕比例，避免原生缩放后标题和卡片放大；软键盘保留内部滚动。逻辑尺寸取整，不因捏合的浮点抖动重复调整渲染缓冲。
- 3D 缓冲调整与重绘在同一次绘制中提交；新视角先准备首帧再替换旧视角。2D 缩放每帧一次 viewBox 更新，不在相机绘制中强制读取布局。
- 业务页面使用统一导航票据处理异步响应；旧视图的详情、错误和一次性链接不得落到新页面。同页刷新合并、草稿和阅读位置保留；原生账户关闭不透传到底层工作台。
- 运行 `npm run verify` 完成语法、回归和构建，发布清单版本从 package.json 读取。

本次仅发布客户端，Go 服务与持久业务数据不变。


## 4.2.0 庭院办公室与公司组织

- 地图采用紧凑分层布局，以中央庭院组织不同面积的部门岛台；连廊、共享客厅、树池、水景和协作长桌构成公共空间。2D与3D保持同一布局，部门及AI分部可以单独聚焦。
- 12个部门、250岗位、249个独立人员的编制。商务与渠道共用经理；总经办董事长和经理分别设岗；AI数据算法部设经理1位、部长5位、员工200位，分成5组40人。
- `src/organization.mjs`统一维护部门、岗位、可见人员、房间、桌位、到岗点和通道。2D与3D消费同一份配置，场景岗位不创建账户、不授予权限、不表示已登录。
- 点击部门聚焦其办公区，已有业务仍从底栏进入。岗位提示显示部门和岗位，人员邀请/编辑使用新的12部门选项，历史部门名称兼容映射。
- 通道图一次编译，真实在线员工和虚拟员工共用路线；静态编制人物不启动250套持续动画。3D通过实例批处理展示组织工位，维持按需重绘。
- 服务端presence支持新部门节点并保留旧地点兼容；审批、身份、库存及历史业务数据协议保持。

全景只展示代表性工位；完整编制仍保留在组织模型中，聚焦部门或分部时局部展开，恢复全景即收起。空闲姿态不产生业务事件、不移动真实在线位置、不提交任务或审批；业务执行、交付、悬浮操作、后台及减少动态效果时暂停。虚拟员工采用蓝色制服，真实员工采用暖色服装，配色集中在 `employee-appearance.mjs`。

信息公开栏位于东南公共区，点击进入公司公告。已登录员工可读取当前公告，管理员和人事可发布、编辑；正文为纯文本，发布人和时间由服务端记录，保存包含幂等与版本检查。便利店位于中庭右下，只提供空间陈设，当前不包含零售交易或支付。
