# 办公室 UI 开发契约

当前生产入口是 `src/index.html` → `src/office.js`。旧实验室的 `styles.css`、`app.js` 和独立登录样式保留历史文件，不加载到这个入口。

## 样式职责

按以下顺序加载本地样式：

1. `ui-foundation.css`：唯一的 `--office-ui-*` 定义、基础字体、控件重置、可见性、焦点、图标和 `#lab` 根容器。
2. `dialog-system.css`：将现有 `--dialog-*` 映射到统一 tokens，提供窗口材质和焦点规则，不决定页面位置。
3. `office3d.css`：3D 场景、场景标签和命中区域。SVG/Three 的设备、人物和房间颜色归场景所有。
4. `erp.css`、`erp-office.css`：业务内容、表单、表格、审批、结果和旧入口隐藏规则。
5. `session-ui.css`：原生账户对话框的内部布局和交互状态。
6. `workspace.css`：三个展示层、窗口位置、底栏、视图工具与响应式布局。

业务模块不能重新定义 `:root`，不能修改 `html`、`body` 或全局 `*` 的字体与主题。新增主题、字号或通用控件规格先修改 foundation；`--dialog-*`、`--erp-*` 只作为兼容别名，不能形成第二套主题。

## 字体、颜色与控件

正文使用 `--office-ui-text-body`，窗口标题使用 `--office-ui-text-title`，控件使用 `--office-ui-text-control`，表头和次要资料使用 `--office-ui-text-meta`。`--office-ui-text-caption` 是 HTML 业务小字下限。金额与数量可用 `--office-ui-font-mono`，不另设整页字体。

普通业务按钮使用 `--office-ui-control-compact` 或 `--office-ui-control-height`；需要更大触控面积的账户操作使用 `--office-ui-control-touch`。输入框使用 `--office-ui-field-height`；移动端输入字号使用 `--office-ui-text-input-touch`，避免输入时浏览器自动放大。圆角使用 `radius-field/control/card/section/window` 对应 tokens。

主色、文字、背景和边框使用 `paper/ink/muted/line/soft/accent/on-accent` 等公共 tokens。单一业务状态的风险色可以留在作用域内；跨模块重复使用时应提升为语义 token。不要用人物或设备的 SVG 色值替代 HTML UI 的主题色。

控件共用完整细边框，不增加阴影或单侧强调条。正文结果、表格和填写内容优先，不通过增加背景卡片或放大标题填满窗口。

## 页面与缩放边界

`#lab` 下有三个同级容器：

- `#workspace-stage`：办公室场景与相机。
- `#workspace-business`：ERP 工作台和后续业务页面。
- `#workspace-chrome`：底栏、视角、通知等操作层。

壳层用一个 `mountWorkspaceViewport([stage,business,chrome], {boundsTarget:lab})` 同步三层的可见尺寸与逆缩放。新增页面不能再创建视口补偿实例，不能给 `body`、业务窗或某个表单叠加 `zoom`、缩放 `transform` 来适配截图。Three/SVG 相机缩放只改变办公室视角，不改变业务文字和底栏。

`workspace.css` 统一设置业务窗口的位置、宽高和底栏预留空间。`erp.css` 只处理窗口内部，保留内容滚动；不再读取 `--workspace-visible-*` 或自行处理 VisualViewport。原生账户对话框在浏览器 top layer，定位补偿由壳层统一传入的视口数据与 `session-ui.css` 处理，不复制一套 viewport 监听。

## 增加业务内容

优先在现有 ERP 工作台增加 section，由 `office.js` 将 `#workspace-business` 传给挂载函数，并接回 `onNavigate/onClose`。不要将业务窗挂到 `document.body` 或办公室的 SVG/canvas 内。底栏继续可操作，关闭窗口后回到当前办公室视角。

沿用现有 `.erp-heading`、`.erp-form-grid`、`.erp-field`、`.erp-button`、`.erp-table`、`.erp-status` 和审批分区。新增局部组件使用独立类名，不覆盖其他模块的根类。权限按钮仍由后端 `allowedActions` 驱动；UI 基础层不包含业务审批规则，也不产生业务数据。

切换模块时保留草稿，后台刷新不重播打开动画，不抢焦点、不重置阅读位置。新增动效必须支持 `prefers-reduced-motion`，销毁时释放帧、监听和计时器。

## 检查与验收

在 `client` 目录运行：

```sh
npm run verify
```

`ui-foundation.test.mjs` 从实际 HTML 入口解析样式及本地 `@import`，检查 token 唯一归属、主题引用、根覆盖、窗口布局职责和 business frame。它不锁定每一种状态色或每个间距。

布局改动还需要浏览器验收：桌面约 980px 业务窗、390px 手机、浏览器缩放/捏合、软键盘、全屏；分别检查办公室、业务窗和底栏是否仍能操作。单据长标题、8 个业务入口、长表格、审批意见和报表结果都应参与检查。样式解析及契约测试不能代替实际画面检查。


## 渲染与异步模块约定

`scene-view.js` 管理场景替换。新渲染器在隐藏的候选层创建，恢复当前展示状态后调用同步 `prepare()` 完成第一帧，成功才移除旧层；准备失败保留旧层。场景的 `destroy()` 必须清掉 RAF、观察器、事件、动画和 GPU 资源。不要通过提前删除旧场景或把画布设为空白来显示加载状态。

`scene3d.js` 的尺寸观察只记录目标尺寸，在一次绘制事务内变更缓冲并重画。镜头缩放不调整 canvas 分辨率。SVG 相机也只写最终 viewBox，不能在一次相机更新中交替读取布局与反复修改属性。视口尺寸取整由壳层完成，渲染器不另做页面缩放。

`erp.js` 用统一视图票据隔离请求：页面详情、错误、反馈和一次性链接只回到发起它们的页面访问；关闭、切页和重开都会使旧票据失效。共享资料按加载周期和读取顺序接纳，首批资料就绪前不生成空选项表单。普通同页刷新合并；所有成功写入提高读取水位，写前旧快照不得覆盖写后页面。新增写操作必须经过共用 `call()`，并等待写后刷新后展示成功结果。

账户对话框保持原生 top layer 和原生焦点管理；底层 ERP 的 Escape 不处理已消费事件或原生对话框内的按键。同一账户窗口重复打开保持输入；会话失效、窗口结束及有效请求结束按既有凭据规则清除敏感字段。

## 发布前操作回归

除自动检查外，基础层或业务窗口结构变化需实际验证：

1. 宽屏与320/390px窄屏打开八类表单，检查长标题、选择框、日期、明细行及提交区域；长表格只在表格内部滚动，页面不横向溢出。
2. 原生捏合1/2/3倍、刷新、2D/3D来回切换：三层位置一致，窗口和底栏物理比例不变，初始镜头完整。
3. 滚轮、双指、旋转、平移、恢复全景和全屏进出：操作不中断，画布不出现空白帧，场景命中区域随镜头更新。
4. 输入未提交表单后切页再回来，核对输入、焦点和滚动；后台轮询不得重建正在编辑的表单。
5. 打开账户后按Escape，只关闭顶层窗口；连续开关业务窗不叠加图层、动画或监听器。
6. 用延迟和逆序响应验证切页、保存、关闭重开：旧内容/错误不串页，保存后立即看到实际结果，写请求只有一次。

截图、浏览器尺寸记录和发布哈希放在忽略的验证目录；测试数据与生产数据隔离。视觉验收不代替权限和业务回归，单元测试也不代替浏览器操作验收。


## 组织地图与步行通道

`organization.mjs` 是部门、岗位、房间、分部、门洞、家具、庭院景观和步行线的唯一数据源。2D 的 `scene-floor2d.mjs` 与 3D 的 `scene3d-layout.js` 只负责将这些数据转换为 SVG / Three 几何，不能各自维护布局坐标。当前世界为 1390 × 1100，采用围合庭院与不同面积的部门空间。新增部门或调整家具时应先修改共享模型，再验证两种视角。

组织岗位不创建账号、在线状态或权限。商务部与渠道部的同一经理有两个岗位，只有主岗位显示人物；真实员工仍通过邀请入驻，在线位置由已认证的 presence 接口更新。不要把地图中的岗位数量用作在线人数。

`floor-routing.mjs` 预先编译正交通道图，并通过 A* 求路；不要在每个角色每一帧重新建立全图。部门入口与人员到岗位置从共享模型推导。布局测试必须覆盖人数与兼任关系、桌面和家具边界、全部部门互通，以及过墙路径只能经过门洞。

部门与分部点击用于聚焦场景，业务办理保留在底栏和实际业务结果页。地图镜头不得替用户提交、审批或生成业务记录。

全景只绘制 `OFFICE_OVERVIEW_SEATS`。显示岗位必须使用 `officeSeatForView` / `officeSeatsForView` 的当前几何，命中区和标签锚点也用这份几何；不能用详情小桌坐标去命中全景大桌。完整岗位数量由原始模型统计。放大仅展开当前一个部门或分部，回到全景收起，避免一次显示整个公司的细节。

`office-ambient.mjs` 统一调度空闲姿态，最多两人、有限时长；场景仅在动作持续时绘制，结束恢复按需渲染。业务、交付和用户互动优先，后台或减少动态效果停止。服装身份统一使用 `employee-appearance.mjs`，不得被任务载荷或个人随机色覆盖。
